## Executive Summary

The current `release/v0.1.8` working tree is not a small patch set. It is a coordinated branch-local update focused on five areas:

1. Tool-loop recovery is more explicit and more persistent, especially when the model emits malformed `tool_call` fragments or keeps retrying actions blocked by runtime policy.
2. Lark/Feishu behavior is upgraded from final-message-only delivery toward draft-progress updates, throttled edits, and configurable ACK reactions.
3. The configuration and runtime surface is widened to cover provider defaults, transport/reasoning overrides, URL-access policy, coordination/subagent settings, MCP/WASM/plugin wiring, and stronger validation.
4. Tool/runtime wiring is updated so browser, HTTP, web fetch, cron update, and search behavior can honor the newer config surface.
5. Onboarding, migration, daemon/doctor diagnostics, and docs/tests are brought forward to match the new branch behavior.

## Branch-Specific Change Areas

### 1. Build and dependency surface

This branch expands the build surface in `Cargo.toml` and the regenerated `Cargo.lock`.

Notable additions:

- `zip` and `quick-xml` for archive extraction and XML parsing paths
- `wasmi` behind `runtime-wasm` for an in-process WASM runtime
- `wasmtime` and `wasmtime-wasi` behind `wasm-tools` for WASM tool/plugin execution
- `aho-corasick`, `rustyline`, `tempfile`, and Unix-only `libc` for runtime helpers, CLI behavior, temp files, and platform handling

Feature-level changes introduced by the branch:

- `runtime-wasm` becomes an explicit optional feature
- `wasm-tools` becomes an explicit optional feature
- the existing branch build examples naturally center around `web-fetch-html2md`, `wasm-tools`, `runtime-wasm`, and `channel-lark`

Practical effect:

- this branch is preparing for broader plugin/runtime scenarios than upstream `release/v0.1.8`
- the lockfile change is structural, not just formatting noise

### 2. Agent loop recovery and malformed `tool_call` handling

The agent/runtime path now treats malformed tool-call output as a recoverable protocol problem instead of immediately ending the turn.

Key changes:

- `src/agent/agent.rs`
  - detects malformed tool-call fragments even when no structured tool call parsed successfully
  - retries when the model looks like it intended to use tools but emitted broken tags or deferred-action text without a valid call
  - preserves per-tool execution success/failure in `ToolExecutionResult` so later recovery logic sees real failures
  - summarizes runtime policy blockers and feeds them back to the model as guidance for the next attempt
  - keeps loop recovery inside the turn until either the model recovers or `max_tool_iterations` is exhausted
- `src/agent/dispatcher.rs`
  - adds XML-style tool-call parsing fallback when native structured parsing yields no calls
- `src/agent/loop_.rs`
  - promotes parsing helpers to shared use
  - adds normalization and summarization for runtime-constraint reasons
  - converts cron delivery injection into a more general default-delivery injection path that can also support `cron_update`
  - generates user-visible retry prompts for missing tool calls and runtime blockers
- `src/agent/loop_/detection.rs`
  - changes loop detection from single warning + hard stop into escalating recovery prompts
  - resets recovery attempts when the model actually breaks out of the pattern
- `src/agent/loop_/parsing.rs`
  - recognizes orphan close tags and more malformed tool-call fragments as parse issues

Behavior impact:

- malformed `</tool_call>` and similar broken output no longer immediately collapse the turn
- repeated policy failures are reframed as actionable blockers, not just opaque tool errors
- loop detection still stops at the iteration budget, but it now tries harder to steer the model away from the bad pattern first

### 3. Lark/Feishu channel behavior and outbound cleanup

The largest branch-local channel work is in `src/channels/lark.rs` and `src/channels/mod.rs`.

#### Lark/Feishu draft and progress flow

This branch adds real draft-update support for Lark/Feishu:

- per-message draft state is tracked in memory
- draft creation, update, finalization, and cancellation are implemented with direct Lark message APIs
- draft updates are throttled by `draft_update_interval_ms`
- total edit count is limited by `max_draft_edits`
- final draft completion can fall back to sending a fresh message if editing fails

Practical effect:

- Lark/Feishu can keep receiving visible progress while tool work is happening, instead of only seeing a final answer

#### ACK reaction policy and group reply behavior

This branch also makes previously stored config actually matter:

- ACK reactions now go through `ack_reaction` policy selection instead of unconditional random reaction dispatch
- constructors respect effective group-reply mention requirements instead of blindly mirroring older `mention_only` behavior
- config-backed values like `group_reply`, `draft_update_interval_ms`, and `max_draft_edits` now propagate into runtime behavior

#### Outbound sanitization and runtime blocker messaging

`src/channels/mod.rs` now does more cleanup and more user-facing explanation:

- strips orphan tool-call closing tags
- drops incomplete tool-call blocks more aggressively
- collects runtime-constraint fragments from tool results and surfaces them in pause/error text
- appends recent runtime blockers when the tool-iteration limit is reached

Practical effect:

- channel users see less protocol garbage
- users get clearer pause messages when progress stopped because of policy or approval constraints

### 4. Config/schema expansion on this branch

The current branch significantly widens the config surface, especially in `src/config/schema.rs` and `src/config/mod.rs`.

#### Provider defaults and runtime overrides

This branch adds provider-aware model resolution and runtime overrides:

- provider-specific fallback model resolution helpers
- explicit `provider` override section
- provider transport selection plumbed into runtime options
- provider reasoning level plumbed into runtime options

Practical effect:

- runtime entry points can choose better default model ids and transport settings without hard-coding one global path

#### New or broadened top-level config areas

The branch adds or expands config sections for:

- `goal_loop`
- `economic`
- `coordination`
- `plugins`
- `mcp`
- `wasm`
- richer security-related config reexports and validation helpers

This is not just schema decoration. Several runtime call sites already consume pieces of these additions.

#### Channel and tool config growth

The branch also broadens channel/tool-related config:

- Lark/Feishu group reply config
- Lark draft update timing and edit limits
- Discord/Slack/QQ/onboarding structs updated to fill new fields
- HTTP request config with `user_agent` and credential profiles
- URL-access policy shared across browser, HTTP, and web-fetch tools

#### Validation hardening

This branch includes a large amount of additional config validation coverage, including:

- URL-access allowlist/blocklist correctness
- URL-access enforcement prerequisites
- HTTP credential profile env/header validation
- OTP and challenge timeout validation
- role inheritance and duplicate-role validation
- syscall anomaly thresholds and baseline validation
- outbound leak guard sensitivity validation
- cost enforcement and route-down hint validation
- coordination/subagent sizing and timing validation

Practical effect:

- more invalid config now fails fast with targeted messages instead of degrading at runtime

### 5. Tool/runtime wiring changes

This branch extends the tool/runtime layer so the new config surface is actually used.

#### Tool registry and runtime plumbing

`src/tools/mod.rs` now exposes and wires additional capabilities:

- MCP client/protocol/tool/transport modules are exported
- WASM tool support is exported
- browser open/browser automation receive extra backend and URL-access settings
- `HttpRequestTool` receives URL-access config, custom user agent, and credential profiles
- `WebFetchTool` receives URL-access policy in addition to per-tool allow/block lists
- `WebSearchTool` receives security context and a configurable user agent
- provider runtime options now carry transport and reasoning level

Practical effect:

- branch-local config additions are no longer dead schema; they are fed into the actual runtime constructors

#### `cron_update` default delivery behavior

`src/tools/cron_update.rs` changes update behavior for one-shot agent jobs:

- accepts `default_delivery`
- applies that default delivery only when the existing job is an agent job, uses `Schedule::At`, is not an internal `__*` job, and the patch did not already specify delivery
- avoids overwriting an already configured delivery target

Practical effect:

- update flows can inherit branch-local channel context without stomping on explicit job configuration

### 6. Security and filesystem guard follow-through

This branch includes a targeted hard-link guard change in `src/security/file_link_guard.rs` and the file tools that use it.

What changed:

- hard-link detection now receives the path as well as metadata
- Windows path handling now uses `fsutil hardlink list` instead of relying only on metadata
- file read/write/edit tools pass the resolved target path into the guard

Practical effect:

- the branch closes a gap where hard-link detection on Windows was weaker than the Unix path

Minor memory-trait diffs in `src/memory/sqlite.rs` and `src/memory/traits.rs` are formatting-level and do not materially change behavior.

### 7. Onboarding, migration, daemon, gateway, and CLI follow-through

Several branch-local changes make the newer config/runtime expectations visible outside the core loop.

#### Onboarding and migration

- `src/main.rs`
  - onboarding now warns that `--no-totp` is currently ignored by onboarding
  - wizard/quick-setup flow is simplified
  - OpenClaw migration is triggered after onboarding finishes, then config is reloaded
- `src/onboard/mod.rs` and `src/onboard/wizard.rs`
  - older `*_with_migration` onboarding entry points are no longer primary flow
  - compatibility wrappers stay present, but explicitly bail when unsupported migration-only flags are used in this build
- `src/migration.rs`
  - migrated delegate-agent definitions now preserve `enabled`, `capabilities`, and `priority`
- `src/onboard/wizard.rs`
  - setup paths fill in newer config fields for Discord, Slack, QQ, and Lark/Feishu

Practical effect:

- branch-local config additions are less likely to be dropped during setup or migration

#### Daemon and doctor

- `src/daemon/mod.rs`
  - scheduler supervisor now starts only when both `cron.enabled` and `scheduler.enabled` are true
  - logs distinguish between cron-disabled and scheduler-disabled states
- `src/doctor/mod.rs`
  - diagnostics now report those disabled-by-config states as expected conditions instead of generic missing-scheduler problems

Practical effect:

- operator feedback is closer to real configuration intent

#### Gateway and runtime option propagation

- `src/gateway/mod.rs`
  - gateway provider construction now includes transport and reasoning-level runtime options
  - gateway tool-chat helper now routes through `process_message_with_session`, even though current webhook call sites still pass `None`

Practical effect:

- the gateway path is aligned with the broader provider/runtime option model on this branch

#### Small CLI/runtime hygiene changes

- `src/bin/mcp_smoke.rs` now forbids unsafe code explicitly
- `src/update.rs` uses fully qualified `std::io::ErrorKind`
- provider/test structs are updated to include newer runtime fields like `quota_metadata`, `provider_transport`, and `reasoning_level`
