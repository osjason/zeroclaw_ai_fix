# Scout Snapshot (2026-03-13)

## Focus
- Reduce code volume via shared abstractions (priority 1)
- Keep behavior compatible + lower Rust test resource pressure
- Prepare for Feishu/Lark progress + cron announce workflow + security-block transparency fixes

## Key Entrypoints
- `src/main.rs` / `src/lib.rs`
- `src/channels/mod.rs` (channel runtime + prompt wiring + progress mode)
- `src/channels/lark.rs` (Feishu/Lark draft updates)
- `src/agent/loop_.rs` (tool loop, retry prompts, runtime constraint prompts)
- `src/cron/scheduler.rs` (cron execution + delivery)
- `src/security/policy.rs` (command allowlist/risk/approval gate)
- `src/config/schema.rs` (autonomy/channel defaults)

## High-Signal Findings
- Non-Telegram channels default to `ProgressMode::Off` (`effective_progress_mode_for_message`).
- Feishu/Lark supports draft edits (`supports_draft_updates`, `update_draft`) but internal progress visibility is filtered by channel progress mode.
- Cron scheduler currently delivers in `announce` mode after run output; no explicit pre-run "about to execute" notification path.
- Runtime constraint guidance already exists (`build_runtime_constraint_retry_prompt`), but blocking details are still distributed across modules.
- `cron_add` / `cron_update` / `cron_remove` / `schedule` duplicate mutation guard logic (`enforce_mutation_allowed`).

## Minimal Verify Seeds
- `cargo test channels::tests::effective_progress_mode_defaults_non_telegram_to_off`
- `cargo test cron::scheduler::tests::run_job_command_blocks_disallowed_command`
- `cargo test tools::cron_update::tests::applies_default_delivery_to_agent_jobs_when_patch_omits_it`

## First Subgoal Candidate
- Extract shared "mutation guard + policy-block message normalization" for cron/schedule tools to cut duplication first, then use the same abstraction to improve explicit block reporting.
